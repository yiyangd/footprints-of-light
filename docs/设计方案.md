# 《光之踪迹》圣经旅程游戏 · 设计与开发方案 v0.1

2026 年 11 月 20 日 · 在线版（可评论、可编辑）：https://claude.ai/artifact/TGNk2b8UR2LjTbkTbHRMxc

## 一页看懂

《光之踪迹》是一款像《光遇》一样安静、温暖、可以同行的圣经探索游戏。玩家是一位“持灯的见证者”，从“起初神创造天地”一路走到使徒的脚踪，最后在新耶路撒冷的生命树下放下自己的灯。先做网页版（Three.js），由教会青少年一起做、一起录视频。

游戏名《光之踪迹》（Footprints of Light）出自诗篇 77:19：“你的道在海中；你的路在大水中；你的脚踪无人知道。”神带领百姓过红海，人看不见神的脚踪；这个游戏要做的，就是把神在历史中看不见的脚踪变成光，让孩子一路跟着走。小样里黑暗中的发光石路、引路之光身后的一串光点，就是“光之踪迹”。（早期工作名是《光之约》Covenant of Light，因为和已有游戏的名字太接近，改了名。我在 Steam、itch.io、TapTap 上没找到叫《光之踪迹》或 Footprints of Light 的游戏；英文 Traces of Light、Trails of Light 已被别的游戏使用，所以英文用 Footprints of Light。正式发布前，建议再查一次商标。）

**我对你需求的理解**

- 圣经是主线：按书卷和年代往前走，尽量忠于经文和历史
- 像光遇：开放的小地图，走、看、经历剧情；不以打斗为主，战争段落可以有轻度挑战
- 收集：每个故事都有信物、一幅画卷、圣经小知识
- 对象是孩子：帮助他们“身临其境”地明白圣经历史
- 先做网页版，以后再做手机和电脑版
- 青少年参与设计、制作、更新，每个阶段都录小视频讲解
- 一点一点开发，代码交给 Codex 写

**五条最重要的建议**

1. 先做一章能玩的，再扩展整本圣经。66 卷是好几年的工程，按“季”分批发布。
2. 内容和代码分开。经文、剧情、收集品写在数据文件里，不会编程的孩子也能做关卡。
3. 每一章都走同一条制作流水线，这条流水线本身就是一次查经。
4. 借鉴光遇的精神，不搬光遇的素材。角色、美术、音乐都要原创。
5. 经文一律用原文（英文 ESV，中文和合本；游戏有 English 和 English + 中文两种模式），并用颜色区分“经文 / 考据 / 想象”，教孩子分辨圣经说了什么、我们想象了什么。

## 1. 从《光遇》学什么，不学什么

《光遇》真正打动人的不是画面，而是“情感设计”：没有战斗，却让人在陌生人身边感到温暖。我们要学的就是这一点，并把它放进圣经的故事里。

**光遇的七个设计支柱（我的拆解）**

| 支柱 | 光遇怎么做 | 光之踪迹怎么做 |
| --- | --- | --- |
| 无声引导 | 几乎没有教程文字，靠光、风、音乐、地形带路 | “引路之光”、风向、动物、钟声带路；经文只在关键时刻出现 |
| 旅程的情绪 | 七张地图各有一种情绪：晨岛好奇、云野欢欣、雨林静谧、霞谷欢乐、暮土恐惧、禁阁沉思、暴风眼牺牲 | 圣经本身就有情绪曲线：创造的惊奇、失乐园的失落、出埃及的拯救、被掳的黑暗、十字架与复活（第 2 节） |
| 先祖的回忆 | 跟随一束光重演先祖的记忆，最后学到一个动作 | 跟随光重走圣经人物的经历，向他们学一个“姿态”：安息、仰望星空、举杖、弹琴…… |
| 探索就是奖励 | 光之翼藏在角落，收集后飞得更高 | 知识陶片、信物藏在角落，收集后灯更亮、滑翔更远 |
| 善意的社交 | 陌生人默认匿名，靠点蜡烛、牵手、动作交流 | 牵手同行、“为别人点灯”；只用预设短语和姿态 |
| 牺牲与重生 | 在暴风眼献出光，重生后回到晨岛 | 十字架与复活；在新耶路撒冷放下灯，“重生”后带着新的眼光再走一遍 |
| 季节与节日 | 定期更新，给人回来的理由 | 跟着教会节期走：圣诞、复活节、五旬节、感恩节 |

**不学什么**

- 不用光遇的任何素材、角色造型、音乐、界面、名字。机制和理念可以借鉴，作品必须原创，这样也更有自己的灵魂。
- 不做付费抽奖、季卡、排行榜。这是事工，不是生意。
- 不开放自由打字聊天。孩子的安全优先。
- 不做“每日打卡”的焦虑循环。用新章节和节期活动吸引人回来。

## 2. 世界观：持灯的见证者

玩家不扮演亚当、摩西或耶稣，而是一位穿越时间的“见证者”，手里提着一盏灯。“你的话是我脚前的灯，是我路上的光”（诗 119:105）；“我们既有这许多的见证人，如同云彩围着我们”（来 12:1）。

**为什么是“见证者”**

- 不让孩子扮演神或耶稣，避开神学上的为难
- 玩家可以靠近、观看、帮点小忙（赶羊、递砖、拾麦穗），但不改变历史
- 同一个角色走完整本圣经，形成一条成长线

**会随时代变样的“考古之灯”**

这是本作最有特色的设计：玩家的灯会换成每个时代真实的陶灯样式。走完整个游戏，孩子也就看完了一部“油灯考古史”。下表是初稿，正好作为考据组的第一个研究任务，请他们再核对。

| 时代 | 灯的样式 | 游戏里何时换灯 |
| --- | --- | --- |
| 起初（创 1–11） | 还没有灯，玩家带着“第一道光” | 第 1 季 |
| 先祖时期 | 碟形陶灯：浅碗边缘捏出一个放灯芯的口 | 第 2 季 |
| 出埃及到士师 | 青铜时代晚期陶灯，灯口捏得更深 | 第 3–4 季 |
| 王国与先知 | 铁器时代陶灯，晚期常见厚实的高底座 | 第 5–6 季 |
| 被掳与归回 | 波斯时期陶灯（待考据组核对细节） | 第 7–8 季 |
| 两约之间 | 希腊化时期的封闭式陶灯 | 第 9 季 |
| 福音书 | 希律式“刀削”陶灯（主后 1 世纪，参太 5:15“人点灯，不放在斗底下”） | 第 10 季 |
| 使徒行传 | 罗马模制圆盘灯，带图案 | 第 11 季 |
| 新天新地 | 不再需要灯：“羔羊为城的灯”（启 21:23） | 终章 |

**首尾呼应：从生命树到生命树**

圣经以一座园子开始（创 2），以一座城结束（启 21–22），两处都有河，都有生命树。游戏也这样设计：

- 伊甸园和新耶路撒冷互为“倒影”：都有从中央流出的河，都有生命树
- 终章里，“那城内又不用日月光照……又有羔羊为城的灯”（启 21:23），玩家放下一路提着的灯
- 放下灯之后“重生”，回到“起初”再走一遍。这一次能看见第一遍看不见的“金线”：旧约里指向基督的伏笔（第 5 节）
- 这对应光遇“献祭—重生”的循环，意义却不同：不是自己献出光，而是真光已经来到

**十二季：光的旅程**

> 示意图：十二季的光与情绪 · 设计意图（图在在线版文档里）

下排小字是每一季的“光的时刻”；走到新天新地之后，玩家“重生”回到起初。

**主城：书卷殿**

- 相当于光遇的“遇境”：一座安静的殿，中间流着“时间之河”，两边是十二季的门
- 你完成的每一幅彩窗画卷，都会装到殿的墙上，阳光透过它照进来。走得越远，殿越亮
- 终章彩蛋：新耶路撒冷有十二个门（启 21:12），正好对应你走过的十二季

## 3. 核心玩法

一章大约 10–20 分钟：在一张开放的小地图里跟着光走，见证 5–8 个剧情节点，沿途收集，最后安静下来，把这一章的画卷挂进书卷殿。

> 示意图：一章的体验循环 · 7 步（图在在线版文档里）

“帮一个小忙”可以没有；“见证”和“安静时刻”每一章都有。

**一章的标准配置**

| 项目 | 数量 |
| --- | --- |
| 剧情节点 | 5–8 个 |
| 信物 | 1 个 |
| 彩窗画卷 | 1 幅，5–7 片（一个节点一片） |
| 知识陶片 | 3–6 张 |
| 经文之光（金句） | 1–3 节 |
| 姿态 | 0–1 个 |
| 轻互动 | 0–1 个（赶羊、搬砖、拾麦穗……） |

**收集系统**

| 收集品 | 怎么得到 | 例子 | 帮孩子学到什么 |
| --- | --- | --- | --- |
| 信物 | 藏在地图里，或完成轻互动 | 橄榄叶、红玛瑙、烧透的砖、朱红线绳、五饼二鱼 | 记住故事的核心物件 |
| 彩窗画卷 | 每个剧情节点给一片，集齐一幅 | 创造之窗（七日） | 按顺序记住故事 |
| 知识陶片 | 藏在角落，鼓励探索 | “起初”的希伯来文、四道河在哪里 | 历史、地理、考古、原文 |
| 经文之光 | 见证剧情时点亮，可做背诵挑战 | 创 1:1 | 背金句 |
| 姿态 | 向圣经人物学 | 安息、仰望星空、同行 | 社交表达；记住人物 |
| 灯的样式 | 进入新时代 | 希律式陶灯 | 物质文化与考古 |

为什么是“陶片”：古人常把字写在破陶片上，考古学叫“陶片文书”（ostraca），著名的拉吉书信就写在陶片上。为什么是“彩窗”：彩色玻璃窗是教会用图画讲圣经的传统，也正是“光透过来”的艺术。每一章的彩窗，由美术组的孩子亲手设计。

**三色文字原则（最重要的教育设计）**

| 颜色 | 是什么 | 规则 |
| --- | --- | --- |
| 金色 | 经文 | ESV 与和合本原文，必须标出处，不改一个字 |
| 蓝色 | 历史、地理、考古 | 注明可信度，如“多数学者认为”“仍有争议” |
| 灰色 | 游戏想象 | 为玩法加的细节，如“帮亚伯找回走散的羊” |
| 绿色 | 思考题 | 留给小组讨论，没有标准答案 |

**双语显示**：游戏英文为主、中文辅助，只有两种模式——**English**（只显示英文，经文用 ESV）和 **English + 中文**（英文在上，中文在下；中文经文用和合本）。默认双语；在标题页选择，游戏里用右上角的地球按钮或 L 键随时切换，并记住上次的选择。经文标签同时标出两个译本（例如“Scripture · Genesis 1:3 · ESV ｜ 经文 · 创 1:3 · 和合本”）；考据、想象、思考两种语言意思一致即可。所有文字都写成 { en, zh }，切换语言时画面不用重新加载。

孩子会自然学会分辨“圣经怎么说”和“我们怎么想象”。这既是对经文的尊重，也是很好的读经训练。

**移动与操作**

- 走、跑、跳、滑翔。滑翔像光遇的飞行，但更克制，用灯的光芒做能量
- 手机：左手摇杆、右手拖动视角；电脑：WASD + 鼠标
- 掉进深水不会“死”，会回到最后站过的安全地方

**战争段落：挑战信心和智慧，不是杀敌**

原则是“暗示而非展示”：不见血，不出现死亡特写；关键时刻用镜头转开、画面淡出、声音和经文来表达。

| 故事 | 玩法 | 经文 |
| --- | --- | --- |
| 基甸三百人 | 节奏玩法：吹角、打破瓶子、举起火把，敌营惊慌逃跑 | 士 7:16–22 |
| 耶利哥 | 绕城行进；第七日绕七圈，吹角呐喊，城墙倒塌 | 书 6 |
| 大卫与歌利亚 | 机弦瞄准的时机挑战，一击之后画面淡出 | 撒上 17 |
| 过红海 | 追逐逃亡：在云柱火柱的光中穿过海中的干地 | 出 14 |
| 尼希米修城墙 | 合作建造：“一手做工，一手拿兵器”，挑战 52 天完工 | 尼 4:17；6:15 |
| 以利亚在迦密山 | 解谜：修坛、浇水、等候天火 | 王上 18 |
| 保罗海难 | 合作救援：让船上 276 人全都平安上岸 | 徒 27:37, 44 |

**同行：为孩子设计的社交**

1. 单人旅程：先把一个人的体验做好
2. 异步同行：看见别的玩家留下的灯，点亮它可以看到一节经文或一句预设的祝福
3. 实时同行：团契小房间（用邀请码进入），看见彼此、牵手同行、一起弹琴、“为别人点灯”（太 5:14–16）

安全底线：不做自由打字聊天，只有预设短语、姿态和经文；不收集真实姓名、学校、位置。

**节期活动（对应光遇的季节与节日）**

| 节期 | 活动 |
| --- | --- |
| 圣诞 | 伯利恒之夜：跟着星走，见牧羊人和天使，收集黄金、乳香、没药 |
| 复活节 | 空坟墓的清晨；以马忤斯路上的同行 |
| 五旬节 | 火舌与“各人的乡谈”：多语言彩蛋，和巴别塔前后呼应 |
| 感恩节 | 收割与感恩：路得拾麦穗 |

## 4. 第一季《起初》（创世记 1–11 章）

### 第 1 章《创造七日》（已做成小样）

核心体验是“世界在你身边被造出来”。玩家从一片漆黑的深水开始，沿着浮在水面上的一条光之路往前走；每到一个节点，就有一日的经文，世界随之改变。

| 节点 | 经文 | 玩家看到的变化 | 奖励 |
| --- | --- | --- | --- |
| 起初 | 创 1:1–2 | 漆黑的深水，风在水面上吹过 | — |
| 第一日 | 创 1:3–5 | 光出现，天地变亮；玩家的灯被点亮 | 信物“第一道光”、彩窗第 1 片 |
| 第二日 | 创 1:6–8 | 水汽升起成云，天空变蓝 | 第 2 片 |
| 第三日 | 创 1:9–13 | 陆地从水中升起，青草和树木从脚下向四周长出 | 第 3 片 |
| 第四日 | 创 1:14–19 | 太阳、月亮、星星出现在天上 | 第 4 片 |
| 第五日 | 创 1:20–23 | 鸟群飞过头顶，鱼跃出湖面 | 第 5 片 |
| 第六日 | 创 1:24–31 | 羊、鹿、狮子在草地上走动；东方亮起两道柔和的光 | 第 6 片 |

- 神不以人形出现，只用光、声音（经文文字）和风来表现
- “有晚上，有早晨”：每一日结束时，天色暗下又亮起，形成全章的节奏
- 隐藏陶片：“起初”的希伯来文；ruach 是灵、风、气息；“各从其类”出现 10 次；安息日的意思；“甚好”和“好”的不同

### 第 2 章《伊甸园》（小样已做到结尾预告）

- 地图：东方的园子，中央有泉，分成四道河流向四方；园子当中有生命树和分别善恶的树（2:8–10）
- 节点：园子（2:8–9）→ 四道河（2:10–14）→ 神的吩咐（2:15–17）→ 命名动物（2:18–20，动物头上显示中文名和希伯来文名）→ 夏娃（2:21–23）→ 结尾预告：蛇出现在树上（3:1）
- 信物“红玛瑙”藏在比逊河边（2:12）。后来大祖司的以弗得肩带上也有两块红玛瑙，刻着以色列儿子的名字（出 28:9–12）
- 呈现：堕落前的亚当、夏娃是“柔和发光的身形”（灰色·想象：有些犹太和基督教传统这样想象，圣经没有明说）。这也自然解决了“赤身露体”在儿童游戏里的呈现

| 节点 | 经文 | 呈现 |

| 天起了凉风 | 创 3:8 | 风声、树叶摇动；他们躲在树后 |
| “你在哪里？” | 创 3:9 | 全屏安静三秒；镜头缓缓转向玩家，这句话也是问我们的 |

- 思考题：神为什么要问“你在哪里”？神不知道吗？

- 信物“头生的羔羊”，陶片引来 11:4“亚伯因着信，献祭与神”：关键在心，不在祭物
- 这是第一季最沉重的一章。建议玩完后在小组里讨论嫉妒、愤怒，和“我是不是弟兄的看守者”

### 第 5 章《与神同行》（亚当的家谱）

很多人读经时会跳过家谱，这一章把它做成一条“时间长廊”。

- 地图：沿河的一条长路，每走一段是一代人；路边十座家，门口站着这一代的先祖，头上显示年岁
- 时间流逝：玩家往前走，天空日夜加速交替，路边的树长大又老去
- 高潮是以诺：“以诺与神同行，神将他取去，他就不在世了”（5:24）。以诺和玩家并肩走（学会姿态“同行”），走到高处化作光
- 陶片：“就死了”在第 5 章出现了 8 次，唯独以诺没有；玛土撒拉活了 969 岁，是圣经里最长寿的人；按家谱推算，亚当去世时拉麦已经 56 岁

### 第 6–8 章概要

- 方舟（创 6–8）：长 300 肘、宽 50 肘、高 30 肘，约合 137 × 23 × 14 米（1 肘约 45 厘米），分三层，门开在旁边，上面留透光处（6:14–16）。玩法：合作建造（以后联机的第一个合作关卡）；动物成对进入；在方舟里“听”四十昼夜的雨；放出乌鸦和鸽子，鸽子叼回橄榄叶（8:6–11）
- 彩虹之约（创 9）：出方舟、筑坛、彩虹出现。这是游戏里第一次出现完整的七色光；学会姿态“仰望”
- 巴别塔（创 11:1–9）：美索不达米亚的塔庙（ziggurat）正是用烧砖和沥青砌成，与 11:3“拿砖当石头，又拿石漆当灰泥”吻合。玩法：帮忙搬砖（想象）→ 言语变乱，人物头上的字变成各种文字，玩家只能用姿态沟通。这正好教会玩家使用游戏的社交系统，也和五旬节（徒 2）前后呼应

## 6. 神学与呈现原则

所有内容都要经过一位牧者或主日学老师审阅。下面八条是建议的底线，最终口径由教会决定。

1. 神不以人的形象出现。用光、声音（经文文字）、云、火、风来表现（出 33:20；约 1:18）。
2. 耶稣以敬重的方式呈现：柔和的光、简洁的面容，不作为玩家能操控的角色，他说的话一律用经文原文。做福音季之前，和牧者一起定下呈现方式。
3. 中文经文只用和合本原文。和合本 1919 年出版，[版权已经过期，属于公有领域](https://en.wikipedia.org/wiki/Chinese_Union_Version)；英文经文用 ESV，它有版权（Crossway）。按 Crossway 的标准使用指引，不经书面许可最多引用 500 节，并且不超过任何一卷书的一半、不超过作品全部文字的 25%，要附上版权声明，也不能放进 Creative Commons 授权的作品。小样剧情用了 41 节；但游戏英文文字里经文占四成多（按中英文全部文字算约两成），这一条有解释空间，正式公开前请填 Crossway 的许可申请确认；完整游戏一定会超过 500 节，必须申请。拿不到许可时，英文可以改用 2023 年[献给公有领域的 BSB](https://berean.bible/terms.htm)。注意：2010 年的《和合本修订版》仍有版权，不要混用。教会常用的《新标点和合本》（1988，香港圣经公会）和 1919 原版只在标点和个别用字上不同，小样用的是新标点和合本的文字。全游戏统一用一个版本；正式公开前，请向圣经公会确认电子文本的使用许可，或改用标明公有领域的和合本数据。
4. 标注出处，不改写，不往经文里“加戏”。游戏想象的部分一律用灰色标出。神版或上帝版由教会决定，程序里可以一键切换。
5. 暴力和死亡“暗示而非展示”：不见血，不出现死亡特写，面向 8 岁以上。少数不适合孩子的段落不做成可玩关卡，只在时间线上用一句经文概括，由属灵顾问决定。
6. 有争议的问题（创造的年代、出埃及的年代、某些考古发现的解读）：写“学者有不同看法”或并列几种观点，不替孩子下结论。
7. 尊重圣经人物：可以温暖、可爱，但不戏谑，不做搞笑角色。
8. 设一位“属灵顾问”：每一章上线前审阅全部文字，并在章节卡上签名。

## 7. 技术方案

用 Vite + TypeScript + Three.js 做 3D，原生 HTML/CSS 做界面，每一章是一个 JSON 数据文件。先做网页，再用 PWA 和打包工具变成手机和电脑应用，始终是一套代码。

| 需要 | 选择 | 为什么 |
| --- | --- | --- |
| 3D 引擎 | Three.js（WebGL2） | 网页原生，资料多，Codex 很熟悉 |
| 工程 | Vite + TypeScript | 启动快；类型检查能帮 Codex 少犯错 |
| 界面 | 原生 HTML/CSS，盖在 3D 画面上 | 青少年容易看懂、改得动 |
| 内容 | 每章一个 JSON，用 zod 校验 | 写错了会立刻报出中文错误 |
| 美术 | 低多边形 + 柔和光照 + 雾；Blender 建模，导出 glTF | 好看、风格容易统一、手机跑得动 |
| 存档 | 浏览器本地存储 | 不需要账号，不收集个人信息 |
| 部署 | GitHub Pages 或 Cloudflare Pages | 免费，推送代码就自动上线 |
| 手机与电脑版 | PWA（可添加到主屏幕）→ Capacitor 打包 iOS/Android → Tauri 打包电脑版 | 一套代码，多个平台 |
| 联机（以后） | Colyseus 或 PartyKit 的房间服务器 | 只同步位置、姿态、预设短语 |

**代码结构**

```text
src/
  core/       渲染、主循环、输入、音频
  world/      地形、水、天空、植物、动物
  player/     角色、镜头、灯
  story/      剧情节点、字幕、效果
  collect/    收集、存档、图鉴
  episodes/   每章专属的场景代码
content/
  episodes/   每章一个 JSON（经文、节点、收集品）
  scripture/  经文数据（ESV、和合本）
public/assets/  模型、贴图、音乐
```

**一章的数据长什么样（节选）**

```json
{
  "id": "gen-01-creation",
  "title": "创造七日",
  "range": "创 1:1–2:3",
  "beats": [
    {
      "id": "day1",
      "at": [0, 40],
      "lines": [
        { "kind": "scripture", "ref": "创 1:3", "text": "神说：“要有光”，就有了光。", "fx": "light" },
        { "kind": "imagination", "text": "你手中的灯，被这第一道光点亮了。" }
      ],
      "rewards": [
        { "type": "relic", "id": "first-light" },
        { "type": "piece", "win": "creation", "i": 0 }
      ],
      "after": "evening"
    }
  ],
  "cards": [
    { "id": "bereshit", "kind": "history", "title": "“起初”的希伯来文", "at": [-1.2, 34.5], "text": "……" }
  ]
}
```

关键是 `kind` 字段：scripture / history / imagination / reflection 四种，对应第 3 节的四种颜色。考据组和关卡组只要改这个文件，就能改剧情。

**性能目标**

- 中端手机 30 帧以上，电脑 60 帧
- 第一章首次下载不超过 10 MB，之后每章不超过 5 MB
- 草和树用 instancing（同一个模型一次画出成千上万个）；尽量不用实时阴影
- 设置里提供画质“低 / 中 / 高”三档

## 9. 青少年团队与制作流水线

每一章都走同一条 8 步流水线，第一步就是一起读经。做游戏的过程本身就是查经。

**分组（建议每季轮换一次，让每个人都试试）**

| 组 | 做什么 | 适合谁 |
| --- | --- | --- |
| 考据组 | 读经、查背景、写章节卡和陶片 | 爱读书、爱历史 |
| 关卡组 | 在纸上画地图，安排剧情节点和隐藏点 | 爱玩游戏、空间感好 |
| 美术组 | 画彩窗画卷、角色和场景草图，学 Blender 建模 | 爱画画 |
| 音乐组 | 录乐器、诗歌、环境声（风、水、羊叫） | 会乐器 |
| 程序组 | 用 Codex 实现功能、测试、提交代码 | 对编程好奇，不需要会写代码 |
| 测试组 | 试玩、找 bug、写反馈 | 所有人 |
| 视频组 | 录制、剪辑开发日志 | 爱拍视频 |
| 属灵顾问（成人） | 审阅经文和神学 | 牧者或主日学老师 |

10–12 岁的孩子适合美术、配音、测试；13 岁以上可以做关卡和程序。

**一章的 8 步流水线**

1. 读：小组一起读这一章的经文（这一步就是查经）
2. 查：考据组查地理、文化、考古，填“章节卡”
3. 写：定下 5–8 个剧情节点、经文原文、信物、陶片、思考题
4. 画：关卡组在纸上画地图；美术组画彩窗
5. 做：用“章节策划提示词”生成 JSON 初稿 → 人工逐字核对经文 → 用 Codex 实现特殊玩法
6. 玩：全体试玩，测试组记录问题
7. 审：属灵顾问审阅全部文字
8. 发：上线，录视频

**每次聚会的节奏（2 小时）**

| 时间 | 内容 |
| --- | --- |
| 0:00–0:20 | 读经与分享（本章经文） |
| 0:20–1:20 | 分组制作 |
| 1:20–1:40 | 试玩新版本 |
| 1:40–1:55 | 录视频 |
| 1:55–2:00 | 祷告 |

```markdown

- 一句话概括：
- 本章情绪：
- 地点与地理：
- 时代与年份（注明依据）：
- 文化背景（衣食住行、职业、习俗）：
- 考古与史料（注明可信度）：
- 剧情节点（5–8 个，每个写经文出处）：

- 彩窗分几片，每片画什么：
- 知识陶片（3–6 张）：
- 金句：
```

## 11. 用 Codex 开发

你不需要先让我写一个 prompt、再回来 prompt 我要计划：计划就在这份文档里，下面的提示词可以直接复制。之后每做一章，都循环用两种提示词：给 Claude 或 ChatGPT 的“章节策划提示词”出方案，给 Codex 的“实现提示词”写代码。

> 示意图：一章从经文到上线 · 含试玩与修 bug 的循环（图在在线版文档里）

蓝色那一步不能交给 AI：经文一定由人逐字核对：英文对照 esv.org，中文对照纸本和合本。

### 使用小贴士

- 把 AGENTS.md 放在仓库根目录。[Codex 每次开始工作前都会先读它](https://developers.openai.com/codex/guides/agents-md)，规则只需要写一次
- 一次只给一个里程碑；改动小，做完就能试玩
- 每次做完，自己在电脑和手机上各玩一遍；有问题就用“修 bug 模板”贴回去
- 用 git 保存每一步（可以让 Codex 帮你提交），出了问题能退回去
- 经文必须人工逐字核对：AI 有时会背错经文
- 这些提示词在 Codex 的命令行、编辑器插件或桌面版里都能用，也适用于其他编程助手。起步工程包里的 docs/PROMPTS.md 是同一套

### AGENTS.md（放在仓库根目录）

```markdown
# AGENTS.md —《光之踪迹》

## 项目
《光之踪迹》（Footprints of Light）是一个网页 3D 圣经探索游戏（Three.js），英文为主、可开中文辅助（English / English + 中文）。玩家是“持灯的见证者”，按书卷和年代走过圣经历史：跟随引路之光，见证剧情（经文原文），收集信物、彩窗碎片、知识陶片、经文和姿态。灵感来自《光遇》的安静与同行，但所有美术和代码都是原创。
开发者是教会青少年（13–18 岁）和带领人；玩家是 8 岁以上的孩子。
完整设计见 `docs/设计方案.md`。

## 技术栈
- Vite + TypeScript（strict）+ Three.js（WebGL2）
- 界面：原生 HTML/CSS 覆盖层，不用 React/Vue
- 内容：`content/` 下的 JSON，用 zod 校验（`src/content/schema.ts`）
- 测试：Vitest
- 部署：GitHub Pages（`.github/workflows/deploy.yml`）

## 常用命令
- `npm install`
- `npm run dev`（手机在同一 Wi-Fi 下测试：`npm run dev -- --host`）
- `npm run build`
- `npm test`
- `npm run validate:content`
- `npm run count:esv`（统计用了多少节 ESV 经文，见第 2 条）

## 目录
- `src/core` 渲染、主循环、输入、音频
- `src/world` 地形、水、天空、植物、动物
- `src/player` 角色控制、镜头、灯
- `src/story` 剧情节点（BeatRunner）、字幕、效果注册表
- `src/collect` 收集、存档、图鉴界面
- `src/episodes/<id>.ts` 每章专属的场景和效果
- `content/episodes/<id>.json` 每章的经文、节点、收集品（中英双语）
- `prototype/` 最早的单文件小样（只作参考，不再修改）

## 必须遵守
1. 经文：只能使用 `content/` 里 kind 为 `scripture` 的文字，必须带出处（`ref` 写成 `Gen 1:3`）。英文用 ESV，中文用和合本（新标点和合本，神版），两种都一字不改，标点照抄。绝不编造、改写、凭记忆补全或自己翻译经文；缺少时写 `TODO(经文)`，并在回复里提醒人工补充。
2. ESV 有版权（Crossway）。按 Crossway 的标准使用指引：整个游戏引用 ESV 不超过 500 节、不超过任何一卷书的一半、不超过游戏全部文字的 25%；游戏里必须保留版权声明（`UI.esvNotice`），并在每段经文旁标出 ESV；含 ESV 经文的内容不能用 Creative Commons 授权发布。每次加经文后运行 `npm run count:esv`，把结果写进回复；超过上限之前停下来，提醒带领人先向 Crossway 申请书面许可。
3. 双语：所有给玩家看的文字都写成 `{ "en": "...", "zh": "..." }`，放在 `content/`，代码里不写死任何一种语言的文字。游戏只有两种模式：`en`（只显示英文）和 `bi`（英文在上、中文在下），默认 `bi`，选择存在 localStorage，切换时不需要重新加载。非经文文字（考据、想象、思考）两种语言意思一致即可。新界面要在两种模式、手机竖屏和横屏下都检查一遍。
4. 每一行显示给玩家的文字都有 kind：`scripture`（金）、`history`（蓝）、`imagination`（灰）、`reflection`（绿）。新功能沿用这四种样式。
5. 内容与代码分离：剧情文字、收集品、坐标写在 JSON 里，不要硬编码在 TS 中。
6. 呈现：神不以人形出现（只用光、声音、云、火、风）；暴力“暗示而非展示”，不出现血和死亡特写；面向 8 岁以上。
7. 儿童安全：不做自由文字聊天；不收集姓名、位置等个人信息；不接第三方统计和广告；不放外部链接（版权声明里的网址只写成文字，不做成链接）。
8. 原创：不使用《光遇》(Sky) 的任何素材、角色造型、名称、音乐或界面。第三方素材只用 CC0 或明确允许的授权，并登记在 `CREDITS.md`。
9. 手机优先：所有操作都支持触屏（左摇杆、右侧拖动视角、按钮）；中端手机 ≥ 30 帧。
10. 性能：draw calls < 150；草和树用 InstancedMesh；纹理 ≤ 1024；每章资源 ≤ 5 MB；不用实时阴影（用圆形阴影贴图）。
11. 可读性：代码注释和回复都用简体中文，写给初学者看；函数短小，命名清楚（游戏里给玩家看的文字按第 3 条双语）。
12. 小步前进：一次只做一个任务；不要顺手大改无关的代码。

## 完成任务前
- `npm run build`、`npm test`、`npm run validate:content` 全部通过；改了经文就附上 `npm run count:esv` 的结果
- 在回复里写清楚：改了什么、怎么在电脑和手机上手动测试、还有什么已知问题
- 改了玩法就更新 `docs/CHANGELOG.md`
```

### 里程碑提示词（一次复制一段给 Codex）

**M0 起步：把小样变成正式工程**

```text
先阅读 AGENTS.md、docs/设计方案.md、prototype/src/ 里的小样源码（index.html、main.js、content.js）、content/episodes/ 里的两个 JSON。

任务：
1. 用 Vite + TypeScript + Three.js 初始化工程。package.json 提供 dev、build、preview、test、validate:content、count:esv 脚本；安装 three、zod、vitest。

6. 写 scripts/count-esv.ts 和 npm run count:esv：统计用了多少节 ESV 经文（上限 500）和经文占全部文字的比例（参考 prototype/count-esv.mjs）。
```

## 12. 风险与对策

最大的风险是做不完，其次是热情下降；两个的对策都是“小步、常有能玩的新东西”。

| 风险 | 对策 |
| --- | --- |
| 范围太大，做不完 | 永远先做“能玩的最小版本”；按季发布，每季都是完整作品 |
| 热情下降 | 每 2 周有一个能玩的新东西；视频带来成就感；节期活动给出目标 |
| 美术风格不统一 | 先定一张“风格板”（颜色、形状、光的规则）；低多边形更容易统一 |
| 经文或史实错误 | 三色文字 + 人工逐字核对 + 属灵顾问签名 |
| 神学分歧 | 牧者早参与；有争议的地方并列观点 |
| 版权 | 原创美术和音乐；经文用公有领域译本；不用光遇素材；第三方素材登记授权 |
| 儿童安全与隐私 | 不做自由聊天；不收集个人信息；视频取得家长同意 |
| 手机卡顿 | 低多边形、instancing、画质三档；每个里程碑都在真手机上测 |
| 代码都是 AI 写的，没人看得懂 | AGENTS.md 要求中文注释；每次让 Codex 解释改了什么；程序组轮流给大家讲一段代码 |
