# 新旧两版对比工具

把小样（`prototype/`）和正式工程（`src/`）各跑一遍同样的操作，逐项比较，用来确认“只是换了写法，画面和玩法没有变”。
M0 的三步都是这种改动，所以每一步做完都跑一次。等小样删掉以后，这个文件夹也可以一起删。

这个工具不参与打包，也不影响网站。不会编程的话不用管它。

## 怎么跑

需要 Playwright（一个能用程序操作浏览器的工具）。Claude Code 的云端环境里已经装好了；自己的电脑上要先在仓库最外层运行 `npm install --no-save playwright` 和 `npx playwright install chromium`。

```bash
# 1. 打包两版
(cd prototype && npm ci && npm run build)
npm ci && npm run build

# 2. 另开一个终端，让正式工程在 4173 端口上跑着
npm run preview -- --port 4173 --strictPort

# 3. 对比（大约 4 分钟）
tools/compare-prototype/run-all.sh
```

结果打印在终端里，截图和详细记录在 `tools/compare-prototype/out/`（不会提交到仓库）。

## 只比文字：diff-content.mjs

```bash
node tools/compare-prototype/diff-content.mjs
```

几秒钟就跑完，不需要浏览器。它逐字比较两边的文字：小样的 `prototype/src/content.js`、`prototype/src/index.html`，和正式工程的 `content/episodes/*.json`、`content/ui.json`。经文、剧情、陶片、界面文字，一个字、一个标点不一样都会列出来（开始页最下面的版本小字除外，那是有意改的）。
小样还在线上的时候，改了任何一边的内容都跑一下它。

## 它是怎么做到“精确比较”的

- `harness.js` 在游戏自己的代码之前运行，把浏览器的时间、每一帧的调度、定时器和随机数都换成假的。这样两版可以一帧一帧同步地走，同样的操作得到同样的结果，位置这些数值能比到小数点后四位。
- `run-one.cjs` 是操作的“剧本”：按空格看剧情、按住 W 走路、跑、跳、滑翔、拖动视角、触屏摇杆、跳过剧情、撞伊甸的门、捡陶片、做姿态、翻图鉴、走完结尾、重新打开页面点“继续”。每到一处记录状态并截图。三种屏幕（电脑、手机竖屏、手机横屏）× 两种语言各跑一遍。
- `diff-state.cjs` 比较记录下来的状态；`diff-pixels.cjs` 逐像素比较截图；`diff-css.cjs` 逐条比较浏览器解析后的样式规则。

## 结果怎么看

2026-11-21（M0 第 1 步做完时）的结果，可以当作“正常”的样子：

- 状态：每种配置约 4000 项，只有 1 项不同，是开始页上那行版本小字（有意改的）。
- 截图：286 张里，游戏中的画面要么完全相同，要么最多差 12 个像素。差的那几个像素是因为两版里物体的绘制先后顺序不同，在两个面深度几乎相等的地方谁盖住谁不一样，肉眼看不出。开始页的三张因为那行小字不同。
- 样式规则：26 项不同，都是打包压缩时等价的改写（例如 `translateX(-50%)` 写成 `translate(-50%)`）。

如果状态多出别的差异，或者某张游戏里的截图差了几百个像素以上，就说明改动影响到了画面或玩法，要查清楚（第五日之后的除外，见下一段）。

**第五日之后本来就不一样，这是有意的。** M0 第 1 步之后，正式工程修了鱼和走兽（鱼只在水里跳，第一次不再跳在地图正中央；走兽不再一出现就集体走向地图正中央，见 `docs/CHANGELOG.md`），小样没有改。所以现在“正常”的样子是：

- 第五日之前（`day4-lights` 和更早的截图）：和上面说的一样。
- 从 `day6-animals` 这张起：状态里每种配置会多出 7、8 项“绘制次数”（`calls`）不同，因为画面里拍到的东西不一样了；游戏里的截图大多会差几十到几千个像素（2026-11-21 最多的一张差约 9500 个，占画面的 1%～2%），差在鱼、涟漪和走兽站的地方。
- 位置、镜头、世界、存档、界面文字仍然应该全部一致。如果这些也不同，或者第五日之前就出现了差异，才要查。

另外，汇总里“手机竖屏”那一行可能写着最大差异 21%：那是开始页的 `91-from-map`，小样那行版本小字折成了两行，整页跟着挪了一点，和游戏里的画面无关。

2026-11-21（M0 第 2 步做完时，界面文字搬进了 `content/ui.json`）又跑了一遍，结果和上面说的“正常的样子”一样：每种配置里，状态只有开始页的版本小字和 7、8 项绘制次数不同，界面文字全部一致；第五日之前的截图除了开始页那行小字，最多差 1 个像素；样式规则仍是 26 项等价的改写。

这个工具在 M0 第 1 步里抓到过两个只看代码发现不了的问题，都出在打包压缩样式这一步：弹窗背后的模糊消失了；`@media` 被改成了旧 iPhone / iPad 不认识的写法。修法分别写在 `src/style.css` 开头和 `vite.config.ts` 的注释里。
